# CUPS Print Server (Docker)

A Docker image that runs a [CUPS](https://openprinting.github.io/cups/) print server, built from the OpenPrinting CUPS source on top of `debian:stable-slim`. It ships with a broad set of printer drivers, a web admin interface, and **automatic AirPrint advertising via Avahi**, so printers you add in CUPS are shared on your network with a single container.

## Features

- **CUPS 2.4.20**, compiled from the official OpenPrinting source release
- **Web interface** on port `631`, listening on all interfaces
- **AirPrint / Bonjour**: Avahi service files are generated automatically for every printer you configure
- **Persistent configuration**: `printers.conf`, `cupsd.conf`, PPDs and `cups-pdf.conf` are kept in `/config` and restored on every start
- **Wide driver coverage**, including:
  - `printer-driver-all`, `foo2zjs`, Foomatic / OpenPrinting PPDs
  - HP drivers (`hplip`, `hpijs-ppds`, `hp-ppd`)
  - Samsung ULD drivers (`suld-driver2`) from the SULDR repository
  - `printer-driver-cups-pdf` for printing to PDF
- **Prebuilt image** on GitHub Container Registry, rebuilt automatically every month

## Quick start

Pull the prebuilt image:

```bash
docker pull ghcr.io/flemmingkrarup/cups:latest
```

Or build it yourself:

```bash
git clone https://github.com/FlemmingKrarup/cups.git
cd cups
docker build -t cups .
```

Run it:

```bash
docker run -d \
  --name cups \
  --restart unless-stopped \
  --net host \
  --device /dev/bus/usb \
  -e CUPSADMIN=admin \
  -e CUPSPASSWORD=change-me \
  -v $(pwd)/config:/config \
  -v $(pwd)/services:/services \
  -v $(pwd)/PDF:/PDF \
  ghcr.io/flemmingkrarup/cups:latest
```

Then open <http://localhost:631> and manage printers under **Administration**.

### Docker Compose

```yaml
services:
  cups:
    image: ghcr.io/flemmingkrarup/cups:latest
    container_name: cups
    restart: unless-stopped
    network_mode: host        # needed for mDNS/Bonjour discovery
    devices:
      - /dev/bus/usb:/dev/bus/usb   # only needed for USB printers
    environment:
      - CUPSADMIN=admin
      - CUPSPASSWORD=change-me
    volumes:
      - ./config:/config
      - ./services:/services
      - ./PDF:/PDF
```

> **Tip:** Host networking is the simplest way to make printer discovery and AirPrint advertising work. With bridge networking, publish `631/tcp` and `5353/udp` and expect discovery to be less reliable.

## How it works

On start, `root/run_cups.sh`:

1. Applies the `TZ` environment variable (if it is a valid zone name) to the container clock.
2. Creates the admin user (`CUPSADMIN`) as a system user in the `lpadmin` group and sets its password to `CUPSPASSWORD`. The password is re-applied on every start.
3. Restores configuration from `/config`:
   - `/config/printers.conf` is copied to `/etc/cups/` (an empty file is created if missing)
   - `/config/cupsd.conf`, if present, **replaces** the built-in `cupsd.conf`
   - `/config/cups-pdf.conf`, if present, is copied to `/etc/cups/`
   - `/etc/cups/ppd` is symlinked to `/config/ppd`
4. Copies any `*.service` files from `/services` into Avahi's service directory.
5. Starts `avahi-daemon`, then the `printer-update.sh` watcher in the background, and finally runs `cupsd` in the foreground.

`root/printer-update.sh` watches `/etc/cups` with `inotifywait`. Whenever you change your printers in the web UI:

- `printers.conf` is saved back to `/config/printers.conf`
- old `AirPrint-*.service` files are removed and regenerated by `airprint-generate.py`
- the new service files are synced to Avahi, so AirPrint clients see the change
- changes to `cupsd.conf` are saved back to `/config/cupsd.conf`

This means **everything you set up in the CUPS web interface survives container recreation**, as long as `/config` is a persistent volume.

## Configuration

### Environment variables

| Variable       | Default             | Description                                                              |
| -------------- | ------------------- | ------------------------------------------------------------------------ |
| `CUPSADMIN`    | `admin`             | Username for the CUPS admin interface                                    |
| `CUPSPASSWORD` | `password`          | Password for the admin user                                              |
| `TZ`           | `Europe/Copenhagen` | Timezone for the container and CUPS logs. Invalid values fall back to UTC |

The CUPS version is a build-time setting: edit `CUPS_VERSION` in the `Dockerfile` to build another release.

### Volumes

| Path        | Purpose                                                                  |
| ----------- | ------------------------------------------------------------------------ |
| `/config`   | `printers.conf`, `cupsd.conf`, `cups-pdf.conf` and `ppd/`                |
| `/services` | Generated AirPrint (`AirPrint-*.service`) and custom Avahi service files |
| `/PDF`      | Output folder for the CUPS-PDF printer                                   |

> **CUPS-PDF output:** the image sets `Out /PDF` and `AnonDirName /PDF` in `cups-pdf.conf`, so printed PDFs land in the `/PDF` volume. To change this, put your own `cups-pdf.conf` in `/config`.

### Ports

| Port   | Protocol | Purpose                  |
| ------ | -------- | ------------------------ |
| `631`  | TCP      | CUPS web interface / IPP |
| `5353` | UDP      | mDNS / Bonjour discovery |

## Default CUPS settings

The image patches `cupsd.conf` at build time so the server is usable from other machines on your network:

- Listens on `0.0.0.0:631` instead of `localhost` only
- `IdleExitTimeout` disabled so the daemon keeps running
- Printer browsing enabled
- Remote access allowed to `/` and the admin locations (admin still requires a user in the `lpadmin`/system group)
- `ServerAlias *` set, so the server answers to any hostname
- `DefaultEncryption Never` (plain HTTP)
- Avahi's D-Bus integration disabled (`enable-dbus=no`)
- CUPS-PDF writes to `/PDF`

To customise further, put your own `cupsd.conf` in `/config`; it takes precedence over the built-in one.

## Security notes

This image is designed for a **trusted home or lab network**. Before exposing it anywhere else:

- **Change the default credentials** (`admin` / `password`).
- Encryption is disabled and the admin interface is reachable from any host. Do not expose port `631` to the internet, and consider firewalling it to your LAN.
- Restrict access by providing your own `cupsd.conf` in `/config`.

## Adding a printer

1. Open <http://localhost:631/admin> and log in with `CUPSADMIN` / `CUPSPASSWORD`.
2. Choose **Add Printer** and pick a detected network or USB printer.
3. Select a driver (a driverless/IPP Everywhere option is best for modern printers; otherwise pick a matching PPD from the bundled drivers).
4. Tick **Share This Printer**. An AirPrint service file is generated automatically and the printer appears on iOS/macOS devices.

## Repository layout

| Path                              | Description                                                        |
| --------------------------------- | ------------------------------------------------------------------ |
| `Dockerfile`                      | Image definition (CUPS build, drivers, config tweaks)              |
| `root/root/run_cups.sh`           | Container startup script (user, config restore, Avahi, `cupsd`)    |
| `root/root/printer-update.sh`     | Watches CUPS config and syncs it to `/config` and Avahi            |
| `root/root/airprint-generate.py`  | Generates AirPrint Avahi service files from CUPS printers          |
| `entrypoint.sh`                   | Legacy entrypoint, not used by the current image                   |
| `.github/workflows`               | CI: builds and pushes the image to GHCR                            |
| `LICENSE`                         | GPL-3.0                                                            |

## CI / image builds

`.github/workflows/docker-image.yml` builds the image and pushes `ghcr.io/flemmingkrarup/cups:latest`. It runs on pushes to `main`, manually (`workflow_dispatch`), and on the 1st of every month at 03:00 UTC to pick up base-image and package updates. Pull requests only verify that the image builds; they do not push anything.

## Updating CUPS

Bump `CUPS_VERSION` in the `Dockerfile` to a release available at <https://github.com/OpenPrinting/cups/releases>, then rebuild.
